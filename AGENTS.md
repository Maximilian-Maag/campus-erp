# AGENTS.md — repository rules

Rules for anyone (human or agent) working in this repository. These are the
source of the executable checks in `tools/policy_check.py` + `policy.json`.

## What this repo is

Documentation and analysis only. It holds a reverse-engineered description of the
HIS-ERP database dump, a module catalogue, a C4 model, and a requirements
baseline. There is no application code.

## Hard rules

1. **Never commit the dump.** `*.backup` is git-ignored. The dump is proprietary
   and must not enter git history.
2. **Never commit personal data.** The dump is Muster (sample) data; do not add
   real personal or financial records anywhere.
3. **Mark inference.** Every non-obvious statement about the system must cite its
   evidence (source page, table name, query) or be marked *(inferred)*. This is
   the point of the repository.
4. **Regenerate, don't hand-edit.** Everything under `schema/` is generated by
   `scripts/`. To change it, change the script and re-run.
5. **No absolute home paths** in tracked files.
6. **Shell style:** `#!/bin/bash`, `[[ ]]` (unquoted vars), `(( ))` for numeric
   tests, two-space indent.

## Policy as code

- `tools/policy_check.py` (vendored, checker version pinned in `policy.json`).
- `.githooks/pre-commit` runs it in `--changed` mode. Enable per clone:
  `git config core.hooksPath .githooks`.
- `.github/workflows/policy.yml` runs it in `--ci` mode.

### Why there is no `tests` section in `policy.json`

The plugin test-harness policy (unit/regression/integration/e2e + mutation) applies
to Omarchy plugin repositories that ship runtime code. This repository ships
documentation plus two shell scripts and the vendored checker, so the harness is
not applicable; `policy_check` therefore reports `tests/layout` as a WARN by
design. If code with logic is ever added here, add the harness rather than
suppressing the warning.

## Re-vendoring the checker

Copy the canonical file and bump the pin:

```bash
cp ~/Work/omarchy-qutebrowser/tools/policy_check.py tools/policy_check.py
# then set "checker" in policy.json to the file's CHECKER_VERSION
```
